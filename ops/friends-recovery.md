# Discord identity and friends recovery

Discord login resolves `discord_id`, never a matching username. A passwordless legacy account can be recovered from the Discord ID embedded in its server-generated Discord avatar URL when exactly one record matches. Owner recovery also requires the configured `DISCORD_ADMIN_ID`. Ambiguous records stop with an account-support error instead of creating another profile. Profiles with uploaded or removed avatars may require explicit identity recovery.

`repair-discord-account.cjs` audits two explicitly selected records by default. Supply `--discord-id`, `--keep`, and `--retire`; add `--apply` only after inspecting the audit. It requires matching Discord avatar evidence and the configured administrator identity for an Owner. It preserves the original profile and settings, merges social references, and retires the duplicate without transferring its old sessions. It writes a protected EJSON backup before mutation. `MONGODB_URI` selects the database; `SIGMOD_IDENTITY_BACKUP_DIR` selects the backup directory.

`ensure-social-indexes.cjs` also defaults to an audit. With `--apply`, it backs up duplicate friend/request pairs, retains one record for each pair, and creates unique friend, request, username, and settings-target indexes. Duplicate usernames or settings targets require manual resolution; this script refuses to choose an account or preference automatically.

The V5 client and backend must be updated together. V5 Discord login starts at `/api/v5/discord/login` and validates OAuth state on callback. WebSocket account binding requires the private `auth-challenge` proof. Older V11 installations need the rebuilt userscript. Logout clears local credentials, revokes V5 sessions, and detaches account sockets. V5 currently runs as one PM2 fork; its account-session and friendship operation queues serialize concurrent operations within that process. Multiple worker processes would require shared serialization or database transactions before rollout.

For the deployed V10 API, `prepare-legacy-discord.cjs <isolated-candidate>` adapts the shared Discord identity service and models to its `mainDB` connection and preserves its existing login redirect. It refuses an unrecognized legacy callback. Build the isolated candidate, then run `verify-legacy-discord.cjs <isolated-candidate>` before copying the four changed source/runtime modules into the legacy deployment. Verification uses provider fixtures and a temporary localhost MongoDB database with a guarded name; it never authenticates a real Discord user. Back up the existing modules before publishing and reload only the affected SigMod process.

Run the repository suite with `SIGMOD_TEST_MONGO_URI=mongodb://127.0.0.1:27017` and `npm --prefix server test`. Integration tests use random, guarded database names and delete only their own fixtures. Without that variable, database integration tests are skipped. Browser account authorization and gameplay remain separate release checks.
